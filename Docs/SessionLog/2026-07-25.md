## What we did

- **Recovered session continuity.** The `/start` recap was stale — it reflected the moment the prior session hit an MCP blocker, not the ~45 minutes of work that followed before the crash. Reconstructed the true state via file timestamps, screenshots, and direct Unity scene inspection: `GridPlacementSystem.cs` and `FreeFlyCamera.cs` already existed with a basic raycast-and-click placement system.
- **Click-and-drag placement.** Left-click-and-hold now lays a straight run of pieces instead of one click per segment. The drag direction locks to the nearest 45° increment (`ComputeDragLineCells`), and nothing is actually placed until mouse-up — a pooled set of ghost objects previews the whole run live, so wandering onto a different 45° line mid-drag just re-previews instead of leaving stray committed pieces behind.
- **Right-click drag deletion**, mirroring the same hold-and-drag model, with a fix so holding still over a stack only deletes one piece per hold (tracked via `lastDeletedPosition`) instead of cascading through everything under the cursor in a single click.
- **Grid-cell alignment fix.** `SnapToGrid` now centers pieces within a cell (`Floor + 0.5`) instead of on cell corners/intersections, so a placed piece's footprint sits flush with the grid lines instead of straddling four cells.
- **Vertical stacking.** `GetNextStackY` finds the top of whatever's already built at a cell and stacks new pieces on it; both the ghost preview and the actual placement commit use this so what you see is what you get.
- **Placement targeting, iterated three times** as the real problem came into focus:
  1. First pass: raycast only against a flat ground plane, ignoring all collision. Fixed the original bug (aiming at a tall wall's base would resolve to the wall's own cell and stack on top of it) but broke adjacency — aiming near a wall from the side would resolve to wherever the ground happened to be, sometimes cells away or behind the wall.
  2. Second pass: `Physics.SphereCastAll` swept along the cursor ray to catch nearby pieces even on a near-miss, snapping to the adjacent cell via the hit face's normal.
  3. Final: replaced the sphere-sweep with a real oversized invisible trigger collider (`PlacementAssist`) added to every placed piece, sized to cover its own cell plus one full cell of reach in every direction at its own height. A single ordinary raycast against that (rounding the hit point to a grid cell) now naturally resolves to the right adjacent cell without any sphere-cast or face-normal math. Deletion's own raycast had to be taught to explicitly skip `PlacementAssist` hits so it stays precise (never deletes "near," only exact).
- **Grid visualization** (`GridVisualizer.cs`, new script): dark-grey `LineRenderer` grid drawn over the ground, matching the 1-unit placement grid. Iterated on distance handling: started as a hard cutoff at a fixed distance, replaced with a real width-based taper (`fadeStartDistance` / `fadeDistance`, both Inspector-tunable) since flicker on thin distant lines is inherent to the geometry, not a setting to tune away.
- **Ground and grid scaled up** from 10×10 to 120×120 units, with HDRP linear fog enabled (25→110) so the enlarged grid/ground fades into atmospheric haze at the edges instead of a hard boundary.
- **Wall material**: started with a procedural mottled-grey stone texture (`Tex_Stone.png`) as a placeholder, then replaced it with the user's own downloaded PBR texture (`PavingStones115A`, albedo + normal map only — roughness/AO/displacement and the redundant DirectX normal variant were skipped to keep this pass simple). Fixed two bugs found along the way: `_BaseColor` was still holding an old flat-placeholder tint that was darkening the new texture toward brown (reset to white), and UV tiling was adjusted (2×4 → 1×2) so bricks read at a reasonable size.
- **Bottom-bar build menu** (`BuildMenu.cs`, new script): procedurally-built uGUI bar with nested categories (currently just "Walls" → "Wall Segment"), data-driven off a `MenuCategory[]`/`MenuItem[]` array so more piece types are just data entries later. Auto-creates an `EventSystem` with `InputSystemUIInputModule` if none exists.

## Decisions & trade-offs

- **Single raycast + real collider over sphere-cast approximation.** The sphere-cast worked, but the user pushed for a cleaner mental model: give the empty grid space next to a wall an actual collider, so a single precise raycast just works. More setup cost per placed piece (one extra GameObject + trigger collider), but conceptually simpler and removes a tunable "how forgiving" radius in favor of an exact, grid-aligned reach.
- **Grid fades by shrinking line width to zero, not alpha.** The unlit grid material isn't set up for transparency, and reworking it for real alpha blending in HDRP is more fragile than just tapering width — visually equivalent for this purpose.
- **Downloaded texture kept intentionally partial** (albedo + normal only). Roughness/AO packing into an HDRP mask map was left out to keep this a fast, simple pass; flagged as a possible later improvement, not a gap that blocked anything.

## Dead ends

- **"Forgiving" ground raycast** (see-through-placed-pieces via `RaycastAll` + math-plane fallback) — built to fix a targeting-precision complaint, but it was solving the wrong problem; explicitly reverted once the user clarified they actually wanted click-and-drag placement instead.
- **Sphere-cast-based adjacency snapping** (`wallSnapRadius`, `TryGetNearbyPieceHit`) — worked correctly (verified) but was replaced by the `PlacementAssist`-collider + single-raycast approach per explicit direction to go back to a single ray.
- **Hard grid hide-distance cutoff** — replaced by the smooth width-based fade once distance-tunability was requested.
