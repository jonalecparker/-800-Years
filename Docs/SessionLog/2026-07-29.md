# Session — 2026-07-28 → 2026-07-29

## Goal

Fix the snapping tension the user felt in hand-testing: the tangent-tied connector sometimes generated huge curves when all they wanted was a joint. Their spec, in their words: reshape the endcap at the snap point so one face still meets the old wall and another can leave in any direction — "all of the curve is happening right there at that snap point," both walls stay straight. Chosen via options: a **rounded node** (implicit round post) over miter/arc-fan, and the tangent tie demoted to a Shift modifier. Three playtest rounds followed, each finding the next seam — and the session ended with the user calling the pattern ("whack-a-mole… we should be able to have a few principles and have the building system arrive out of it") and a decision to rebuild the core on a **node/edge graph** next session.

## What we did

- **Corner nodes** (`WallNode.cs`, new): snapped ends become node ends (`nodeAtStart/nodeAtEnd`) that cap flat exactly ON the shared point — end extension stands down, junction scan starts past the post radius. The node renders the joint: an implicit round post (radius = half thickness) every member's faces are tangent to, meshed as only the **exposed arc wedges** between adjacent members (sort inward bearings; each gap exposes gap−180°). Collinear butt ⇒ no post, L ⇒ quarter barrel, hairpin ⇒ rounded tip, 90° tee ⇒ flush butt, 8° tee ⇒ one shoulder arc — one rule, any angle, any member count, zero cut geometry at joints. `Connect` is multi-pass and order-critical (flag all → retract flagged hosts → rebuild other members); a node losing its second-to-last member dissolves and un-nodes the survivor. `TryEndSnap` slimmed to 3 candidates (endpoint + two flanks; the cap candidate died with the overshoot). Tangent tie inverted to Shift-opt-in.
- **Unification round** (user playtest, two screenshots — both the same root cause, the sub-10° duplicate check firing where a joint was wanted): **flank nodes** — `TryFlankSnap` lands a drag's far end ON any wall's face as a T at any angle, the host joining the node as a half-plane member, geometry untouched; **same-node stand-down** — members never band, graze, or duplicate-block each other (`ignoreWalls` through `BuildSpecs`→`FindJunctionBands`/`IsCrossingHost`/`IsBlocked`; overlap = legal `buriedInMember` masonry); the one refusal left is a wall whose EVERY piece is buried (redraw along a member). Supporting fixes: 3m bound on cut-plane ride-along, node scan margin past box-corner grazes, gate re-judging against local tangents.
- **Anchor-side face snap** (user picked "option 2" after a UX walkthrough): hovering near any wall face snaps the anchor ONTO the face point on the **cursor's side** — click plants it, drawing away is the same flank node. Replaced the old lay-flush-alongside hover gesture (parallel runs are the Offset tool's job). The curve tool's chord phase discards the hover's cursor-side flank pick and re-derives anchor-side — a chord overshooting the host would land on the far face.
- **Walls never intersect** (playtest round 2, item 1): junction bands are now classified — a band the sweep passes THROUGH (opens after the body starts AND closes before it ends, `Band.through`) **refuses its span red** instead of cutting, at any angle; committing places only the clear side spans ("two walls, one on each side" in one gesture). Terminal burials — an END inside the band: contact T-fuses, collinear gap bridges, cap-entry redraws — still cut flush. `PendingIgnores` only stands a flank host down when the wall leaves on its face's side, so dragging across your own anchor host refuses too.
- **Rectangular snap ghosts** (item 2): the half-buried gold post marker is gone; node-forming snaps (endpoint or face) preview as `BuildSnappedStubPreview` — a token chord leaving the point along `outDir`, node-capped flat ON it, a rectangle wholly outside the host. Click-release commits that stub as a real node joint. Drag-time post cylinders show only at endpoint ends.
- **Flush 90° placement** (item 3, the camera-angle stubs): two causes — flank-anchored drag direction was freeform (followed the cursor, hence the camera correlation), and `TryFlankSnap.stubYaw` was 90° off (stub lay along the host, not out of the face). Now a flank-anchored drag **steps its direction from the face normal** (always, 15°; Alt frees) — a lazy short drag lands exactly perpendicular.
- **The graph decision**: diagnosis delivered — walls are independent objects whose relationships are *inferred* by physics probes after the fact; every gesture spawns ambiguous overlap cases needing new classifiers; the last two sessions were building graph behavior (nodes, joints, stand-downs) on a non-graph data model. Decided: rebuild on nodes/edges (edges never overlap, meet only at nodes; nodes own all joint geometry; placement = graph editing), **crossings auto-split into a 4-way node**, next session, fresh. Full brief in `Docs/WallGraphRebuild.md` — principles, what dies (bands, grazes, cut planes, gates, IsBlocked, ignore lists, Links), what survives (sweep meshing, wedge renderer, vertical math, all assists), suggested build order.
- **Infrastructure detour (~40 min)**: the editor relaunch left the MCP bridge dead — the plugin's "Auto-Start on Editor Load" pref was off, so restarts (unlike domain reloads) never reconnected. ## Decisions & trade-offs

- **Rounded node over miter/arc-fan**: one implicit post handles every angle and valence with zero cut geometry; the wedge rule *generates* the special cases (flush butt, quarter barrel, shoulder arc) instead of enumerating them.
- **The node owns the joint; walls stay straight** — turning lives at the point. Tangent-tied auto-curving became Shift-opt-in rather than default.
- **Contact ⇒ connect survives, crossings don't**: an end riding its overshoot into a host is deliberate joining (cut-fuse); a sweep passing through and continuing is an intersection (refuse red). The classifier is body-relative — a band is terminal iff it begins before the body starts or outlives its end.
- **Always-on 15° stepping from a face anchor**: buys exact perpendiculars at the cost of shallow draw-*away* angles (draw *toward* the face instead, or Alt). Flagged for playtest.
- **Graph rebuild over continued patching**: the user's "few principles" instinct, made concrete. Auto-split chosen over refusal for crossings because under the graph it *is* their rule — two walls each side — with the bookkeeping automated.

Replaced by the body-relative rule the same hour.

# Session — 2026-07-29 (second session): the wall-graph rebuild

## Goal

Execute `Docs/WallGraphRebuild.md`: rebuild the wall system core on a node/edge graph — relationships stored, never inferred — then iterate the snap/ghost UX from live user feedback. All six build-order steps landed in one pass (data model, edge meshing, node meshing, placement, delete, courses), not just the core-session estimate.

## What we did

- **`WallEdge` + `WallEdgeSection` (new)**: an edge between exactly two `WallNode`s with a quadratic `control`, cut into uniform sweep sections — terrain-stepped bases, locked tops, world-anchored UVs all carried over. Geometry depends only on its own nodes/control/heights/terrain: no probes, no cut planes, no rebuild cascades, no end extensions (sections always span [0,1]; the extended-arc machinery died). Stacked courses are edges too: `stackBase` + `tMin/tMax` coverage, sharing the base's nodes and curve so all t-parameters agree; never part of the planar graph.
- **`WallNode` rewritten**: members are edge-ends; the wedge rule is the ONLY joint renderer. Flank members died exactly as briefed — a T splits its host, so all members are end members and valence handles the rest (90° T/X render nothing exposed; shallow tees one shoulder arc). Posts read end-section spans and climb course stacks, so they rise with courses. Empty nodes dissolve via `OnMemberGone`.
- **`WallGraph` (new, static)** — the only mutator: `CommitEdge` (end-node resolution: existing node / split-the-edge-under-the-point / new free node; crossing detection via polyline intersection, no physics; exact polar-form `SubCurve` subdivision; sub-edges chained through crossing nodes), `SplitEdgeAtMany`, `DeleteSections` (kept section ranges → sub-edges, new flat-capped tip nodes at hole boundaries, orphan dissolution), `CommitCourse` (lays only `UncoveredRanges` — double-stacking impossible), `RebuildStackOver` (splitting/deleting a based edge remaps the whole course stack onto the survivors — masonry never floats), `OverlapsExisting` (the one refusal left: near-exact redraw, <3° / <0.15m / >0.6m sustained).
- **`GridPlacementSystem` rewritten** onto graph ops (name kept for scene refs): same gestures and assists; `TryEndSnap`→`TryNodeSnap`, `TryFlankSnap` lands on the host **centerline** (commit splits the host into a T at any angle); whole-gesture red refusal replaces per-spec blocking; commit/delete/offset all route through `WallGraph`. Preview meshes are never transferred — commit rebuilds fresh.
- **Deleted `SplineWall.cs` + `SplineWallSection.cs`** — bands, grazes, ClipRow, the 10° gate, IsBlocked, buildOrder, ignoreWalls, buriedInMember, EndExtension, Links, hasGaps: all gone. Net ≈ −1,200 lines while adding crossings, stack remapping, and partial courses.
- **Verified programmatically in play mode**: L-corner (quarter barrel), 90° T-split (flush, valence 3), X auto-split (valence 4, both walls split), diagonal chained through an existing node, mid-edge hole delete (two sub-edges + tip nodes), full delete with node dissolution, course stacking (aligned, posts rise, re-course no-op), redraw refusal, locked-top surviving splits, and a coursed wall crossed mid-run (stack remapped onto both halves). Zero console errors; screenshots confirmed clean joints.
- **Four UX rounds from user feedback**, same day:
  1. **Flat ends**: valence-1 nodes render nothing (the flat cap IS the finish) — the rounded 180° tips shipped and were flattened at user request. **Square stub**: `StubLength` tied to `gridSize` (the old square footprint had come from end extensions growing a 10cm token chord).
  2. **Ghost clipping + side-of-end snaps**: flank previews trim their display back to the host's face (`TrimInto`, `SubCurve` display trim) while `pendingCommit` keeps the true centerline gesture for the graph; wall ends regained side-face hit points.
  3. **The user's insight**: an end stub commits identically regardless of approach face or ghost angle — so all directional presentation went away. Node hovers now **highlight the members' existing end sections gold** (no stub, no round post marker); a bare click on a node commits nothing; round post ghosts survive only at pending **crossing** points mid-drag.
  4. **Angle freedom**: the always-on 15°-from-normal stepping off faces is gone — direction is fully free everywhere; **Shift = 5° stepping** (absolute bearings free-drag, from the face normal on flank anchors, so a lazy Shift-drag lands 90° flush). Scene's serialized `angleStep` updated 15→5.

## Decisions & trade-offs

- **Narrowest possible refusal**: the graph doesn't care about shallow V's, hugs, or flush parallels — interpenetration near joints is legal masonry, crossings split at ANY angle (no 10° gate). Only a true coincident redraw refuses. Playtest may want tuning.
- **Crossing tolerances**: within 0.35m of a gesture end → the end's own node; within 0.3m of an existing node → threads through it; crossings closer than 0.5m merge. Hand-unvalidated.
- **Preview ≠ commit at flank ends, deliberately**: display trims/tucks are cosmetic; the graph always receives the centerline gesture it needs to split hosts. `pendingCommit` formalizes the split.
- **Courses cascade with their base** (unlike the old floating/stale courses): split the base, the stack remaps; delete under a course, the course above clips. Honest masonry over preserved geometry.
- **Node presentation is direction-free** (user's call): the node is the anchor, angle is the drag's business.
