# Session — 2026-08-02: storeys are a number, and the ray names which one you meant

## Goal

The **storeys half** of the ⚠ storeys/stairs design session, then a long playtest tail. Going in, a wall standing on another wall was a *course* — a second kind of object riding a base edge. Coming out, it's an ordinary edge with its own nodes and a `baseY`. Stairs were not touched; that half of the design call is still open.

The session ran in five rounds: the rebuild, then four rounds of user-reported findings from building second storeys.

## What we did

- **Courses are deleted, not dormant** (`WallEdge`, `WallGraph`, `WallNode`, `GridPlacementSystem`). Gone: `stackBase`, `IsCourse`, `CreateCourse`, `BuildCourseSpecs`, `UncoveredRanges`, `CommitCourse`, `RebuildStackOver`, `StackTopOver`, `WallRoom.NotifyCourseLaid`, and the post stack-climb. **The reason was rooms, not tidiness**: a course was never a node member, and `WallGraph.FaceAt` can't trace a non-member, so a course could never be part of a room's ring. An ordinary edge with its own nodes can — so an upper storey can be a room.
- **The planar graph is per-base** (`WallGraph.SameBase`, 0.25m tolerance, −inf = terrain, −inf never matches a finite base). It filters `FindCrossings`, `OverlapsExisting`, `CoincidentCoverage`, `ResolveEndNode`, the distance/alignment guides, and **node identity** — `WallNode` carries its own `baseY` and `FindAt` takes one, because nodes are stored at y=0 and an upper wall's ends land directly above the lower wall's node. This closes last session's "the planar graph is height-blind" item, which was listed as owned by this design call.
- **Wall top faces are build surfaces** in both cursor resolvers (`TryGetCurveTarget`, `TryGetBuildSurface`) — a top-face hit reports `hoverBaseY = section.topY` and sets `hoverRideHost`.
- **A run anchored on a wall top is a SPAN of the wall below, never a direction.** `RideOnto` puts the point on the host's centerline and pulls it to the host's own ends; `TryRideControl` gives the edge the host's exact curve via `WallGraph.SubCurve` (polar-form subdivision). Nothing overrides it — not the bulge wheel, not Shift, not R. **Alt is the only way out**, and it keeps the storey while dropping the host.
- **A ride follows the masonry THROUGH its nodes** (`RideChainEnd` / `Walk` / `StraightestContinuation`). It used to clamp at the host's ends, so stacking a circle took eight drags and a room took four. The walk consumes a host, takes the straightest continuation on the same storey out of the far node (dot > 0.2, so it never doubles back), and stops where the cursor's nearest point falls mid-host. Each span still becomes its own edge with its host's exact curve — `pendingCommit` became a **list**, and every gesture now goes through it.
- **A snapped point can be standing on a wall too** (`RideHostUnder` / `AdoptRideHostUnder`). The lock used to be reachable only by a top-face raycast, so snapping to the END of a short second storey (the ray hits that wall's *side*) handed back free direction exactly where a player goes to extend it. The query is geometric — an edge of another storey, within half a thickness in XZ, whose section-top **range** brackets this base. Deck hits are exempt, which keeps deck building free-form.
- **`WallEdge.skirt`**: how far below `baseY` the masonry actually starts. `StackFit` buries the joint (`skirt` = base − lowest covered host top) and pins `fixedTopY` to clear the **highest** covered top by the dialed height. `baseY` remains the storey — node identity and every planar filter — so a skirted wall still welds to unskirted neighbours.
- **`SnapHeightOf` measures from the wall's own floor** (`fixedTopY` − terrain for a ground wall, − `baseY` for a stacked one). Measuring a storey's height from the terrain beneath it is nonsense, and the skirt is not height.
- **A null base means the TERRAIN storey, never "any storey"** (`BaseMatches` → `WallGraph.SameBase(edge.baseY, atBase ?? -inf)`), and **the cursor ray names the storey even on a side hit** (`hoverSnapBase`). See "Bugs hit", round 4 — these two are the fix for it.
- **`ModifierHints`** gained the stacking contexts (straight and curved) and the wall-top hover, per the standing rule that the panel is edited in the same commit as the keys.

## Decisions & trade-offs

- **Storeys as `baseY`, not a second object kind.** The deciding argument was the room ring, above. Everything else (posts growing at upper corners with no special case, delete surgery needing no stack remap) fell out of it for free.
- **Burial (`skirt`) over a per-section bottom profile.** An unlocked host's top *steps* with the terrain, so a flat-bottomed stack leaves daylight over every low step. A baked bottom profile is the real fix — the upper wall would step with its host — but it has to survive `SubCurve` reparameterization and serialization for marginal graybox benefit. Burial closes the gap today; the profile is the answer if stacked walls should read as stepping rather than as a level parapet.
- **8 segments per circle stays** (user asked directly whether circles need to be multiple nodes). 4 quadratic arcs bulge ~6% off a true circle; 8 is 0.3%. The segment count is right, so the fix was to make the ride chain *through* nodes rather than to coarsen the geometry.
- **No structural rules yet** (user's call, restated this session): nothing stores what rests on what. Build without rules first, add them later — `baseY` alone is enough to reconstruct support when that lands. The known consequence is accepted: deleting a lower wall leaves masonry above it hanging in the air.
- **A ride adopts its host's height** like every other snap, and **honours exactly one snap** — a node on its own storey. A node already sits on the centerline the run is locked to, so honouring it costs the lock nothing.
- **The gesture keeps its ANCHOR's storey for the whole drag.** The old `shapeBaseY ?? deckY` / `roomChainBaseY ?? deckY` fallbacks are gone; with terrain-null they would let a ground rect's side snap onto a deck it happened to run past.

## Dead ends

- **Lowering `baseY` to bury the stepped joint** — caught before writing a line. `baseY` is node identity *and* every planar-query filter, so a buried wall would silently stop welding to its unskirted neighbours. That's what `skirt` exists for.
- **`StackFit` pinning the top from the hovered section** (`topY = baseY + height`). Anchoring low on a sloped host put the new top *below* the high end's masonry — the run sank into its own foundation. Replaced with `max(baseY, highest covered top) + height`; on a level host the two numbers are identical.
- **`RideHostUnder` comparing the host's top at a single parameter** to `baseY` within 0.25m. An unlocked host's top ranges over metres on a slope, so the support query found nothing on exactly the walls that needed it. Replaced with a range bracket.

## Bugs hit

Four rounds of user playtest findings, all fixed:

- **Round 1a — the click-stub overhung a wall-end post by half a thickness.** The stub was centred on a point that pulls to the host's own end. `BuildRideStubPreview` now builds the stub as a span of the host, slid inward to fit.
- **Round 1b — free direction at the end of a short second storey.** Fixed by `AdoptRideHostUnder` (above).
- **Round 1c — daylight between storeys with lock-top off** (user screenshot). Fixed by `skirt` / `StackFit` (above).
- **Round 2 — building on a circle stopped at every node.** Fixed by ride chaining (above).
- **Round 3a — two upper walls built from opposite ends wouldn't meet.** The ride branch bypassed `TryNodeSnap` entirely. `RideDragEnd` now tries a node snap first and re-runs the chain to that node's exact point with the end-pull suppressed (`rideExact`, or it slides past the node onto the host's cap), discarding it unless the chain lands within 0.15m.
- **Round 3b — the ghost's height flipped by 0.5m when the cursor crossed a wall's top edge.** Reproduced exactly: `cursor on the side → snapHeight 3.00 → height used 3.00`; `cursor ON the top face → snapHeight none → height used 3.50` (the dialed height). Grazing a wall's side adopted its height; standing on it didn't. Now it does.
- **Round 4 — the hover flipped between a correct side snap and a red ghost on the storey above.** Root cause was neither the ride nor the refusal: snaps compare XZ alone, so a wall and the wall stacked on it are a dead tie, and the storey filter's `null` meant *any storey*. Node snaps outrank flank snaps and an upper wall's end node sits directly above the lower wall — aiming at the lower wall's side put the raw point **0.50m** from the upper storey's end node, inside the 0.75m radius, so the hover jumped a storey, the ride locked to the wall below, and the ghost drew along the wall already standing there. A ~1.5m-wide dead zone around *every* upper wall's end. Fixed by the two `BaseMatches` / `hoverSnapBase` changes above.

Self-inflicted, worth remembering:

- **Four false alarms from my own play-mode probes, not code regressions**: ray origins at y=20 when the terrain is at y≈54 ("straight down onto the top face" reported no hit); probing a wall's side at a fixed y taken from `SectionsInOrder()[0]`, which overshoots where the wall steps down with terrain; reflection tests leaking hover state between probes (the hover fields are cleared once per frame in `UpdateBuild`, **not** inside `TryGetCurveTarget` — reset all of them before each probe); and a `NullReferenceException` from calling `.GetProperty("Value")` on a boxed `Nullable<ValueTuple>` (boxing yields the underlying value directly).
- Compile round: `CS0618 GetInstanceID()` obsolete in the ride cache key; `Object` ambiguous between `UnityEngine.Object` and `object` in `execute_code`; `using` directives are illegal in an `execute_code` body (it runs as a method body — fully qualify instead).

## Open at end of session

- **Stairs are untouched** — the other half of the ⚠ design call. You can now build a keep with three storeys and no way to climb it.
- **Circle and rect don't get the skirt** — they build one shared `EdgeParams` for the whole figure, so a stacked circle on a stepped host will show the gaps the wall tool no longer does.
- **The room chain's live segment is a straight chord**, so riding a *curved* wall top follows the centerline at the ends but doesn't bend along it. The wall tool does; the room tool doesn't.
- **Elevated rooms get no floor slab** — a room designated on an upper storey has nothing to stand on.
- **A room's roof reads its own ring edges' tops**, so drawing a wall on top of a room's low wall does *not* make that room roofable. Courses used to do this via `NotifyCourseLaid`; `WallRoom.RetryRoofless` now fires on every `CommitEdge` instead, which is not the same thing.
- **You can no longer grab an upper wall by hovering the terrain near it** — you have to point at the wall. Correct per the per-base doctrine, but it's a real change to reach and it hasn't been felt in play.
- The centre-castle playtest is *still* unfinished, now interrupted across two sessions.
