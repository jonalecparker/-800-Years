# Session — 2026-08-18/20: the stone goes triplanar and stops repeating

*One conversation spanning the 18th into the 20th. One arc: the user
asked for the material upgrade offered at the end of the detailing
order — stochastic hex tiling plus world-space triplanar — and both
shipped as a single custom Shader Graph. The debugging middle was a
lesson in how Shader Graph fails silently; the user's first close look
then caught a real artifact the technique brings to structured
patterns, fixed with a height-aware blend.*

## Goal

Kill the visible texture repeat on the big curtain walls and make
stone courses align across separately-built pieces — the
"stochastic/hex tiling in Shader Graph" item offered on 08-17, plus
world-space triplanar, both taken up at once.

## What we did

**1. `StoneTriplanarHex.shadergraph` + `.hlsl`** (new,
`Assets/Shaders/`). The graph is a minimal HDRP Lit graph authored as
JSON directly (MultiJson format learned from package samples, object
serializations copied from shipped graphs) — one custom-function node
sourcing `StoneSurface_float` from the HLSL file, feeding BaseColor /
NormalWS / Metallic / Smoothness / Occlusion blocks. The HLSL does all
the work: **world-space triplanar** (three plane projections of the
absolute world position — `GetAbsolutePositionWS`, since HDRP's
"world" is camera-relative and swims), **hex-grid stochastic tiling**
per plane (each hex lattice cell gets a random UV offset, three taps
blended; offsets only, no rotation, so one ddx/ddy pair serves all
taps and normals need no counter-rotation), and **POM re-implemented
inside it** (marched on the dominant plane only, secant refinement, on
the same hex-blended heightfield the color samples). Normals via
whiteout triplanar blend.

**2. `Mat_Wall_Stone` switched in place.** Property names deliberately
mirror the HDRP/Lit ones (`_BaseColorMap`/`_NormalMap`/`_MaskMap`/
`_HeightMap`/`_BaseColor`), so the existing textures carried over with
no re-assignment, and `_BaseColor` is flagged `isMainColor` so the
palisade tint clone (`material.color`) still lands. Every wall, post,
slab, stair, buttress and merlon inherited the new stone in one
stroke — the point of one shared material. Dials: `_TileSize` 2.4m,
`_PomAmplitude`, `_PomSteps`, `_BlendSharpness`, `_AORemapMin`,
`_NormalStrength`. The old detail map is DROPPED (close-up grain) —
flagged to the user, restorable in the HLSL if missed.

**3. The height-aware blend** (the 08-20 fix, caught by the user's
first close screenshot: "some of the bricks have turned into squiggly
lines with multiple 90 degree turns… others lost their mortar").
Raw barycentric cross-fading of a STRUCTURED pattern interleaves brick
edges from the three offset copies and averages brick against mortar —
fine for noise-like textures, wrong for masonry. `StoneHexAt` now
biases the three weights by the height map and sharpens hard
(`STONE_HEX_CONTRAST` 12): wherever copies compete, the proudest stone
wins outright, each region shows ONE clean copy, and the transition
snaps into the mortar recesses where a wandering boundary reads as
natural coursing. The POM marches the same selected heightfield.
Verified at the same wall face: bricks whole, mortar continuous, wide
shot clean.

## The debugging middle (most of the session)

The first working version took hours of ghost-chasing because three
unrelated failures stacked:

- **Geometry-typed slots on a custom-function node fail silently.**
  The CFN was first authored with Position/Normal/ViewDirection
  MATERIAL SLOTS as its own inputs. Shader Graph's requirements
  gathering ignores those on a CFN, so the GBuffer pass compiled
  against a struct missing `AbsoluteWorldSpacePosition` — `invalid
  subscript`, walls rendering as depth-only ghosts. The fix is
  explicit Position/Normal/View Direction NODES wired in as plain
  Vector3 inputs. A clean template graph rendering correctly beside
  the broken one was what isolated it.
- **Variant errors log ONCE, then cache.** After the first error was
  read and the console cleared, re-renders produced no new message —
  a broken shader and a clean console at the same time. The error
  only reappeared after clearing while forcing a fresh compile.
- **`_DepthOffsetEnable: 1` survives the shader switch.** The material
  had it from HDRP/Lit's POM; `HDShaderUtils.ResetMaterialKeywords`
  re-derives `_DEPTHOFFSET_ON` from the float forever. Zero the float
  itself.
- **`manage_camera`'s positioned screenshot caches by parameters.**
  Four "verification" captures at identical coordinates were
  byte-identical files (md5-proven) — the render never re-ran. Nudge
  the camera every shot.

  broken.

  probe render) — the render probe's own camera was below-terrain
