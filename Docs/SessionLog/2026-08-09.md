# Session — 2026-08-09: walls hug the rim, stairwells return as stamps, and everything gets an undo

*One long conversation (two compactions) in two arcs: the morning picked
up last session's declared goal — walls along the foundation edge — and
brought stairwells back as stored stamps; the afternoon was a
quality-of-life sweep the user drove feature by feature (stone on slabs,
right-click undo everywhere, wall chaining, the 0.5m-step mystery, and a
stair rework). It ended with the user declaring the builder proven
enough: **next is the economy design session (near-arc step 4).***

## Goal

Make building the permanent castle feel right: the foundation-edge snap
last session asked for, then whatever the hand-build turned up.

## What we did

**1. Walls hug the foundation rim** (`TrySlabRimSnap`,
`GridPlacementSystem.cs`) — last session's declared pick-up point,
answered as snap-to-edge (not auto-perimeter):

- `hoverSlabTile` tracks the slab the cursor stands on — top face OR
  side face, since a ray just past the rim hits the prism's skirt and
  that's still an aim at this slab.
- The snap pulls the point to the outline **inset half a wall
  thickness**, so the wall's *outer face* lies exactly on the slab edge.
  It grabs the anchor and the drag end alike, in the wall tool and the
  room chain, so a drag along a foundation edge lands corner-miter to
  corner-miter. It yields to Shift's angle stepping, like the flank.

**2. Stairwells return — as STAMPED wells on floor slabs**
(`SlabTile.Well`, save schema v4): the 08-08 rebuild said "a stairwell
is drawn around," and the hand-build said that's not enough — a stair
committed under an existing floor needs a hole.

- A `Well` is a polygon hole through a floor slab with a stored
  **owner** (`WallStair`), stamped at commit time — floor drawn over a
  stair, or stair committed under a floor — and stored, never
  re-derived. Deleting the stair closes its wells and the floor heals
  (the delete tool's job). Foundations never carry wells.
- Triangulation bridges each well into the cap keyhole-style (the ear
  clipper learned that a bridged seam's repeated vertices sit exactly ON
  the ears they duplicate — skip coincident points or nothing clips),
  with inward-facing side bands down the well's throat.
- `SlabTile.Rebuild()` re-meshes in place, **recomputed from stored
  facts, never read off the transform** — the cutaway may be holding
  this very slab sliced when the stamp lands.
- **Schema v4**: `SlabData` carries wells; the owner travels as a
  positional stair index (-1 = ownerless, which just never heals).
  v2/v3 saves load unchanged.

**3. The ray-transparent roof** — found after the user corrected a
wrong diagnosis ("The bug is not me pointing through the well. I am
definitely pointing at the roof"): **a disabled MeshCollider skips its
re-bake silently** and stays ray-transparent forever after re-enabling.
The cutaway disables colliders it hides, so a well stamped into a
hidden roof left a roof you could see but whose delete ghost landed on
the foundation. `Rebuild` now re-cooks with the collider forced enabled,
then restores its state; the cutaway re-asserts itself next frame.

**4. Slabs wear the wall's stone** (`SlabTile.BuildPrism` UVs): caps =
world XZ metres (the wall-top convention); side bands = ring-run metres
for U, worldY ÷ `CourseHeight` (3.5, = `baseWallHeight`) for V — a
foundation's skirt shows the same courses as the masonry beside it.

**5. Right-click is UNDO, everywhere a gesture chains** (user request):

- Arbitration: a right-**drag** is still camera orbit; a clean
  right-**click** (≤4px travel, tracked centrally per frame, ignored
  over UI) reverses the previous placement.
- Foundation/floor chains pop the last corner (popping the anchor
  abandons the outline). The room chain pops its last leg — vertex,
  ghost, and the already-baked live segment (bake counts recorded per
  leg). The wall tool pops the last committed chain leg (below).
- **Delete got it too** (user request, same session): right-click in
  the Delete tool restores a **whole-world snapshot** taken before every
  delete commits. `CastleSave` split into `Capture`/`Apply` shared by
  Save/Load and new `Snapshot`/`RestoreSnapshot` — the undo goes through
  the same door a load does, so fidelity is total (wells reopen with
  owners, terrain ops replay, everything re-foots). One step deep;
  the snapshot dies on leaving the Delete tool (`SetMode`/`StandDown`),
  so a stale undo can never roll back later work.

**6. Walls chain like the room tool** (user request): committing a
straight wall re-anchors the gesture on the commit's own end node
(`created[last].nodeB`), carrying storey, height, and snap state — Esc
ends the chain (walls stay). Each leg records its created edges
(`WallChainLeg`); right-click deletes the last leg's edges through
`DeleteSections` and re-anchors at the leg's start. Host splits aren't
in `created`, so undoing a leg never deletes what it merely crossed.

**7. The 0.5m-step mystery — banker's rounding** (user's report: "i
only get .5m steps when starting from 1m. if i start from 10.5m and go
down i get .25m. odd."): the min-height clamp (0.25 × 3.5 = 0.875m)
lands exactly on a quarter-grid **half-tie**, and `Mathf.Round`
ties-to-even — so alternate notches rounded the same way and the
display jumped 0.5m. Reproduced exactly in a float32 simulation
(sequence 1, 1, 1.5, 1.5, 2 — the user's report verbatim). Fix:
**round-half-up** (`Mathf.Floor(x + 0.5f)`) in `CurrentWallHeight` and
the new stair dial. Doctrine: never `Mathf.Round` a value onto a grid
whose ties are reachable.

**8. The stair rework** (design discussion, then the agreed first
slice): on a 10.5m wall a stair is enormous and unplaceable in tight
rooms. Agreed direction — make the pieces compose now; a
folded/switchback stair is the designed future answer for tall walls.
Shipped:

- **Width 1.2 → 1.8m** (`WallStair.width` + the scene-serialized copy).
- **Ctrl+scroll dials the climb height** (`stairRiseDial`, quarter
  steps, clamped [2 risers, the wall top]; at the top the dial reads
  "the wall top" and clears). A half-height flight is now a stated
  choice — the landing pattern's first half.
- **R cycles**: flip side → perpendicular (out from the wall, one
  straight span, never blocked) → back. Host change re-arms.
- **The foot reads what it stands on** (`StairFootRest`): the run's
  start point — offset from the wall face on the cursor's side —
  samples the highest wall top or floor slab under it (lintels skipped),
  and if that stands above the host wall's floor and at least a riser
  below the target, the flight starts THERE and `baseFrom` adopts the
  plane, so treads sit on the landing instead of skirting down its
  face. This is what makes the landing pattern work: half-height stair,
  landing, second half-height stair placed by pointing at the tall wall
  from the landing.

## Decisions & trade-offs

- **Delete undo is a snapshot, not per-object restore** — full fidelity
  through the tested load path beats a parallel resurrection system;
  scoping it to the delete-mode session answers staleness.
- **Wall-chain undo's known limit**: a later leg that splits an earlier
  leg's edges makes that earlier leg's undo partial. Rare; the delete
  tool covers it.
- **Stairs**: widen + dial + perpendicular now; the folded/switchback
  stair (landings built in) is the eventual tall-wall answer, deferred.
  Player-built landings are already possible and now pleasant.
- **Rim snap over auto-perimeter walls** — the outline is a polyline
  the chain gesture already rides well; one-click perimeter walls can
  come later if hand-building the rim ever feels like a chore.
- **The user's phase call**: the builder isn't *proven* but the path is
  visible — "I think that's enough." Next: the economy design session
  (Roadmap near-arc step 4, design doc #16), starting with the 1220
  landowner research pass.

## Bugs hit

- The two false alarms during stair-foot verification were both **test
  bugs**, not code bugs: comparing against a different section of an
  UNLOCKED landing wall (whose top steps with terrain), and a
  hard-coded floor height from a previous test's wall. Locked-top
  re-run: rest = 39.75 exact.
- The wrong well diagnosis (§3) — the user's correction was the pivot.
- `stairWidth` is scene-serialized: changing the script default alone
  does nothing; the scene instance was set via editor code and saved.
