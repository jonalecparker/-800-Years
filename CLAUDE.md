# -800 Years — working notes for Claude

Unity 6 / HDRP castle-builder graybox. Session workflow: `/start` to recap, `/wrap` to archive+commit — `Docs/NextSession.md` and `Docs/SessionLog/` are the project memory; read them, not this file, for current state.

## The wall graph (2026-07-29)

The wall system is a **node/edge graph** (`Docs/WallGraphRebuild.md` was the brief; it shipped 2026-07-29). Relationships are **stored, never inferred** — the old physics-probe machinery (junction bands, graze lanes, cut planes/ClipRow, the 10° gate, IsBlocked, buildOrder asymmetry, ignore lists, end extensions, Links, hasGaps) is deleted, not dormant. Don't reintroduce inference; every structural question is a graph question.

- **Model**: `WallNode` (point + member list) and `WallEdge` (exactly two nodes + quadratic Bézier `control`, height data, sections). `WallGraph` (static) is the ONLY mutator: `CommitEdge`, `CommitCourse`, `DeleteSections`, `SplitEdgeAtMany`. Edges meet only at nodes and never overlap or cross — illegal states are unrepresentable. An edge's geometry depends on nothing but its own nodes/control/heights/terrain, so **nothing ever rebuilds because a neighbour changed** (only node posts remesh).
- **Placement is graph editing** (`GridPlacementSystem`, name kept for scene refs): click = node, drag = edge. Snaps resolve to nodes: `TryNodeSnap` (any node within 0.75m), then `TryFlankSnap` (mid-edge **centerline** point; commit splits the host there — a T at any angle, host end zones ±0.9m excluded). Free ends get 1-valent nodes. **Crossings auto-split**: `FindCrossings` (polyline intersection, no physics) → each becomes a shared 4-way node — both walls split via exact polar-form subdivision (`SubCurve`), gold post ghosts preview the pending joints. Crossings within 0.35m of a gesture end collapse into the end's node; within 0.3m of an existing node they reuse it (chain-through).
- **The one refusal left** (`OverlapsExisting`, whole ghost red): a near-exact redraw along an existing wall — <3° relative tangent, <0.15m centerline distance, sustained >0.6m. Everything else is legal: shallow V's, flush parallels, drags across a flank anchor's host (now just a T + crossing, no more red).
- **Nodes own all joints** (`WallNode.RebuildMesh`, the old wedge rule promoted to sole renderer): implicit post radius = half thickness, member inward bearings sorted, each gap exposes gap−180° of arc. Valence 1 = nothing (the edge's flat cap IS the finished end — free ends and delete-hole boundaries cap flat), collinear butt = nothing, L = quarter barrel, 90° T/X = flush (zero exposed arc), shallow tee = one shoulder arc. Flank members no longer exist — a T splits the host so ALL members are end members. Posts read end-section spans; an upper-storey wall has its own nodes, so its corners grow their own posts with no stack-climbing special case.
- **Storeys are `baseY`, not a separate kind of object** (2026-08-02): stacked courses are **deleted, not dormant** — `stackBase`, `IsCourse`, `CreateCourse`, `BuildCourseSpecs`, `UncoveredRanges`, `CommitCourse`, `RebuildStackOver`, `StackTopOver` and the post stack-climb are all gone. A wall standing on another wall's top (or on a slab) is an ordinary edge with its own nodes, so it can be a member of a room's ring — which a course never could, since `FaceAt` can't trace a non-member. That was the reason to cut them, not tidiness. **Wall top faces are build surfaces, and stacking has no free direction** (2026-08-02): both cursor resolvers — `TryGetCurveTarget` (wall tool) and `TryGetBuildSurface` (room / circle / rect / designate) — report `hoverBaseY = section.topY` on a top-face hit and set `hoverRideHost`. **A run anchored on a wall top is a SPAN of the wall below, never a direction**: `RideOnto` puts the point on the host's centerline and pulls it to the host's own ends within `endpointSnapRadius`, the drag end slides along that host whatever the cursor is over, and `TryRideControl` gives the edge the host's exact curve via `WallGraph.SubCurve`. Nothing overrides it — not the bulge wheel, not Shift, not R (the hover stub takes the host's bearing). The click-stub is a span of the host too (`BuildRideStubPreview`, slid INWARD to fit): centred on a point that pulls to the host's own end, it hung half a thickness of masonry off the cap. **Alt is the only way out**, and it clears `hoverRideHost` while keeping the storey. Both were added because a second storey that can wander off its own foundations is not a storey. Building on a room *deck* stays free-form; the lock is wall tops only. **The one thing a ride still snaps to is a node on its own storey** (`RideDragEnd`, 2026-08-02): two upper walls built from opposite ends have to close on ONE node, and a node already sits on the centerline the run is locked to, so honouring it costs the lock nothing — the walk re-runs to the node's exact point with the end-pull suppressed (`rideExact`, or it would slide past the node onto the host's cap) and is discarded unless the chain actually lands within 0.15m of it. **A ride also adopts the host's height** like every other snap: without it, crossing a wall's top edge with the cursor flipped the ghost between the dialed height and the host's, because grazing the SIDE adopts and standing on TOP didn't.
- **A ride follows the masonry THROUGH its nodes** (`RideChainEnd`, 2026-08-02): it used to clamp at the host's ends, so a circle (8 quadratic arcs — 4 would bulge 6% off a true circle, 8 is 0.3%, so the segment count is right) took eight drags to stack and a room took four. The walk consumes a host, takes the **straightest continuation on the same storey** out of the far node (`StraightestContinuation`, dot > 0.2 so it never doubles back; a T upstairs picks the run that carries on), and stops where the cursor's nearest point falls mid-host. An anchor sitting ON a node retries the walk through the node's *other* member, or dragging backwards off a node would do nothing. Each span still becomes its own edge with its host's exact curve (`BuildRidePreview` → one `pendingCommits` entry per span, committed in order so they meet at shared nodes) — **`pendingCommit` is a LIST now**, and every gesture goes through it.
- **A snapped point can be standing on a wall too** (`RideHostUnder`, 2026-08-02): the ride lock used to be reachable only by a top-face raycast, so snapping to the END of a short second storey (the ray hits that wall's *side*, no top face involved) handed back free direction exactly where a player goes to extend it. Both snap branches now call `AdoptRideHostUnder`, which asks the geometric question — an edge of another storey, within half a thickness of the point in XZ, whose section-top RANGE brackets this base. Range, not the top at that parameter: an unlocked wall's top steps down a slope. Nothing stores what rests on what (structural rules stay deferred), so this is asked in exactly two places — that snap, and `StackFit`. Deck hits are exempt (`slabRoom != null`), which is what keeps deck building free-form.
- **A stacked wall's bottom is `baseY − skirt`, and only `baseY` is the storey** (2026-08-02): an unlocked host's top steps with the terrain, so a flat bottom at the hovered section's top left an open slot over every lower step. `StackFit` buries the joint — `skirt` = base − lowest covered host top — and pins `fixedTopY` to clear the HIGHEST covered top by the dialed height (measuring from the hovered section instead would sink the run into its own host when you anchor low on a slope; on a level host the two numbers are equal and nothing changes). `WallEdge.skirt` is geometry ONLY: `baseY` remains node identity and every planar-query filter, so a skirted wall still welds to its unskirted neighbours. `EdgeParams.skirt` defaults to 0, which is always safe; surgery copies it. Applies to the wall tool and the room chain, **not** to circle/rect (those build one shared `EdgeParams` for the whole figure).
- **Delete is edge surgery** (`DeleteSections`): kept section ranges → sub-edges; a mid-hole makes two new 1-valent tip nodes; a fully-deleted edge detaches and empty nodes dissolve (`OnMemberGone`). No linked rebuilds, no gap flags — survivors were never derived from the dead.
- Assists: length stepping relative to the anchor (`lengthStep` 0.5, Alt frees); direction is **fully free everywhere** — Shift steps it in `angleStep` 5° increments (absolute bearings on free drags, **measured from the face normal** on flank-anchored drags, so a lazy Shift-drag off a face lands exactly 90° flush); snapped-height adoption (anchor > drag-end > hover; Ctrl+scroll overrides via `heightOverride`); lock-top; distance guides; angle arc; Offset tool (commits through `CommitEdge`, so it splits what it crosses); `C` tangent-tied connector (only when both snapped ends have a single outward direction — valence-1 node or flank). **Shift means angle stepping and nothing else, in the wall tool and the room chain alike** (2026-08-01): it outranks a flank landing — the stepped bearing wins and the run probes `SteppedLandingReach` (2m) past the cursor to MEET the host, landing on its centerline at the stepped angle (`TrySteppedLanding` in the wall tool, the crossing clamp in room mode). 1m is not enough: `FindCrossings` drops crossings within 0.35m of the probe's own end. Approaches under ~40° can't reach and stay free — honest, not silent. Node snaps still outrank Shift (only one of a point and an angle can be honoured), and the **tangent-tied connector moved to the `C` key** to free Shift for this. Node-snap hovers highlight the members' existing end sections gold (no stub, no post markers — posts preview only at pending crossing points); a bare click on a node commits nothing.

## Vertical math is spans, not layers

- `WallEdgeSection.bottomY/topY` is the source of truth. Never assume uniform section height or ground at y=0 (terrain exists; slice ground = min of sampled corners, quantized down by `baseStep`).
- Bulge (0.5m) and foundation bases (0.5m) are deliberately **stepped** so separately-built structures align — don't make those continuous. Wall height is the exception: it scrolls **smoothly** (Ctrl+scroll, `heightScrollRate` 0.25m/notch, raw ±120 Windows deltas normalized), and alignment comes from snapping — a snapped ghost adopts the host's exact height. A **locked-top host matches by top elevation**, not stored height (`SnapHeightOf` = `fixedTopY` − the wall's own floor: terrain at the snap for a ground wall, `baseY` for a stacked one — measuring a storey's height from the terrain beneath it is nonsense, and the skirt is not height), and `fixedTopY` survives splits.

## Rooms, floors, roofs (2026-07-31)

A room (`WallRoom`) is a **designated** enclosed face of the graph — a stored ring of `WallGraph.DirEdge`, never re-inferred. Same doctrine as the graph itself.

- **The room tool has two jobs** (2026-08-01), picked in the menu's item row under Room: **Build** (chain walls into a new room, the default — `SetMode(Room)` always resets to it) and **Designate** (hand an EXISTING enclosure a floor and roof). Designate is the answer to "I drew a room, it failed, I fixed the wall, and nothing re-checked" — nothing else in the graph re-checks, and nothing should, since a bailey is an enclosed face too. It has **no gesture**: it outranks the Circle/Rect helpers in the dispatch, hover outlines the eligible face, a click designates, and a refused click **says which** of the three reasons applied.
  - Eligibility is **provenance, not shape**: `WallEdge.roomBuilt` is stamped by room-tool gestures (`EdgeParamsNow(..., roomBuilt)`), copied onto sub-edges by every surgery site in `WallGraph`, and a face qualifies when room-built spans are the majority **by length** — a room may borrow someone else's flank, but a bailey ringed by curtain walls never qualifies however room-shaped it looks. Faces already carrying a room are refused (`WallRoom.ContainsPoint`).
  - The hover outline draws the **footprint** (`WallRoom.FaceFootprint`, inset to the inner faces), never the ring: the ring runs down the middle of the masonry, where a guide line is buried inside the wall and invisible. That bug shipped once.
  - `WallGraph.FaceAt` traces every edge both ways each hover frame — fine at this scale, revisit if edge counts reach the hundreds.
- **Every new graph mutator must call the room hooks** — `WallRoom.NotifySplit` (splice sub-edges into rings, reversed when `!forward`), `NotifyBreach` (dissolve), `NotifyCourseLaid` (retry roofless rooms). A mutator that skips them leaves rings pointing at destroyed edges.
- Roof rests on the **dominant crown** — the elevation carrying the most boundary length, ties to the lower — and returns a **reason string** on failure; keep it that way, the log's honesty is the feature. A span *below* the plane always refuses (the deck would hang over a gap). A span *above* it is allowed only when its contiguous run touches a node with a member outside the ring (`LeavesRing`) — borrowed masonry that continues past the room, which the deck butts into at its inner face while the wall carries on up. A wall of the room's **own** ring left off-level still refuses. `roofNote` carries the "roofed at X, the N wall stands Ym higher" line into the BuildLog.
- The roof deck is flush (top AT the wall tops, footprint inset to inner faces). Coplanar surfaces are fine when they face opposite ways; same-facing coplanar z-fights — don't "fix" the inset by extending the deck to the outer faces.
- `WallRoom.All` holds broken rooms until Unity's deferred `Destroy` runs — test `room.broken`, never registry counts, in the same frame.

## Stairs, doorways, the cutaway (2026-08-04)

Briefs: `Docs/Stairs.md` and `Docs/Doors.md` hold the *why*; they move in here once playtested and become history. Only the cross-cutting constraints are below.

- **A stair is a rider (`WallStair`), a doorway is edge data (`WallEdge.Opening`)** — and the split is deliberate. A stair belongs to two storeys, so it gets its own object, its own `All` registry, and membership of no `WallNode`: it never splits a wall, no wall splits it, and no planar query sees it. A doorway is a hole in ONE wall's masonry, so it lives on the data the sections derive from and the doctrine holds. Don't promote a doorway to a rider (it could only cut its hole by inference) or demote a stair to a `WallEdge` variant (it would need an `isStair` flag every query filters out).
- **Every mutator that makes sub-edges must call `WallEdge.CarryOpenings`** — same two sites, same line, as `sub.roomBuilt = edge.roomBuilt`. And every new `WallRoom` hook list now includes `NotifyStairBuilt` / `NotifyStairGone` beside the split/breach ones.
- **`WallEdgeSection.openingIndex >= 0` means NOT solid masonry.** A lintel's bottom is the doorway's head, metres up; a threshold's top is its sill. Anything reading `bottomY` as "the ground this wall stands on" must skip them — `WallRoom.BuildFloor` (a single doorway made a room think it was an upper storey) and `MasonryFloorAt` both learned it the hard way.
- **A section's footing is a property of the wall's GRID, not of where a section boundary happens to fall.** `BuildSpecs` settles the cell count and each cell's footing from the edge's arc alone, then cuts openings into it. Openings used to re-divide the wall, and since a footing is the lowest ground under a footprint snapped down, longer sections sit lower — cutting a door into a short partition sank the masonry beside it. Windows and arrow slits cut into the same grid.
- **A doorway spanning a step reaches DOWN to the lowest cell it covers and UP to the highest** — threshold meets the ground, lintel meets the wall. One figure for both leaves a notch in the wall top, every time, on the high side.
- **Any raycast reading `hit.normal.y > 0.7f` must ask `CutawayView.IsCutSurface` first.** A sliced wall's exposed cross-section has an upward normal exactly like a real wall top; three resolvers do this, and a fourth that didn't would offer to stack a storey at the wall's real top, metres above what's being pointed at.
- **`CutawayView` slices by transform Y-scale about the object's own bottom** (every mesh here is a vertical prism), so view state stays out of geometry and nothing rebuilds because the cut moved — the collider rides along, which is the whole point: what you can see is what you can hit. **Never read `Renderer.bounds` for a vertical span** — a sliced renderer reports the *slice*, and reading it back switches the cut off one step above wherever it sits. That's what `CutawayPivot`'s one cached float is for.
- **The stair's length is DERIVED from the rise, so there is no pitch refusal** — don't add one back; it would police a freedom that was never granted. The only refusal is "not enough wall". Stair width and door width/head are fixed for the same reason: dialing them needs a fifth scroll-wheel meaning, which must join `ClaimingScrollWheel`.
- **Wells and sills are written at the two moments they can become true, never re-derived** (`NotifyStairBuilt`/`TryBuildRoof`, `FloorServing`/`RaiseSills`). This is the `FindCrossings` pattern — a geometric question asked at commit whose *answer is stored* — not the forbidden spatial "what is under me". Sill raising is one-way on purpose.

## Build mode and walk mode (2026-08-05)

`WalkMode` (on `Main Camera`) puts you on your own feet inside what you drew. `Tab` toggles. It exists to *judge* the builder, which is the only reason any of the above is finished.

- **`WalkMode.Active` is a static flag every per-frame system reads** — `FreeFlyCamera`, `GridPlacementSystem` and `BuildMenu` stand DOWN on it rather than being enable/disabled. Each holds state a frozen `Update` would strand: a half-drawn gesture, a ghost left in the air, a cutaway still slicing. **Any new system that ticks every frame has to decide, in the same commit, whether it stands down** — and standing down is deliberate work, not an absence of it (`GridPlacementSystem.StandDown`).
- **The stand-down MUST clear the cutaway** (`CutawayView.Clear`). The collider rides the slice — that's the feature in build mode and a castle you walk straight through in walk mode.
- **The walker IS the camera**: a runtime `CharacterController` with its capsule hung *below* the lens (`center.y = bodyHeight/2 − eyeHeight`). Eye height is therefore baked into `center`, so changing one means changing both. Added at runtime on purpose — build mode wants no capsule in the world at all.
- **Walk mode carries its own readout and stays out of `ModifierHints`** — same precedent as the cutaway: that panel reports what the *tool in hand* reads, and this is a mode switch.
- **Escape belongs to the Unity editor — never take a second meaning for it.** It drops the Game view's focus, and an unfocused Game view has *no* cursor state applied to it, neither lock nor hide. Binding it to "exit walk mode" put you back in with a loose pointer every time.
- **Do not try to fix mouse-look over Remote Desktop.** `Mouse.delta` returns zero against a screen edge and `CursorLockMode.Locked` pins only the *reported* position while the physical cursor roams ([Unity issue tracker](https://issuetracker.unity3d.com/issues/mouse-dot-delta-returns-zero-when-moving-the-cursor-against-the-screen-edge-when-using-a-remote-desktop-connection)). Four fixes were tried and reverted — re-asserting the lock (a no-op unless the state *changes*), warping plus `Mouse.delta` (double-counts), per-frame drift detection (misses a slow creep), and manual centring off position (systematic round-trip error, spins the camera). The implementation is deliberately the ordinary one.

## Save/load (2026-08-05)

`CastleSave` (F5/F9, `Saves/castle.json`) serializes the graph and riders; geometry rebuilds on load.

- **Every new stored fact must join `CastleSave` in the same commit** — a field added to `WallEdge`/`WallRoom`/`WallStair` that isn't serialized silently vanishes on load. This is the serialization face of stored-never-inferred: if it can't be re-derived, it must be saved.
- **Load restores, never re-derives**: `WallRoom.Restore`, not `Create` — no `RaiseSills`, no `TryBuildRoof`, no `NotifyStairBuilt`. And load is NOT a graph mutation: `WallEdge.Create`, never `CommitEdge` — no splits, no crossings, no room hooks. The save came from a legal graph; restore it wholesale.
- **`-Infinity` travels as a `-1e30` sentinel** (`Pack`/`Unpack`) — JSON has no infinity. Any new float field with the terrain-sentinel convention must go through them.
- Identity is positional (index within the file); nothing needs cross-save identity yet. `Saves/` is deliberately committed — the permanent castle save is a project artifact.
- F5/F9 are build-mode only (loading would swap the world out from under a walker) and stay out of `ModifierHints` by the cutaway precedent.

## Elevated ground (proto-storeys)

- Room slabs are **build surfaces**: `WallEdge.baseY` (default −∞) raises a section's bottom, and slab hits are detected by collider name (`"RoomRoof"` → `roofY`, else `floorY`). Any new raycast that can hit a slab must decide deliberately whether it's ground.
- **`EdgeParams` is a struct**: an object initializer that omits `baseY` gets **0, not −∞**. Set it explicitly everywhere, including tests.
- Snaps are storey-filtered (`BaseMatches`) and adopt a host's storey (`AdoptSnapElevation`) — a gesture on a deck must never grab the masonry a storey below. **A null base means the TERRAIN storey, never "any storey"** (2026-08-02): `BaseMatches` is now just `WallGraph.SameBase(edge.baseY, atBase ?? -inf)`, matching what `TrySteppedLanding` already fed `FindCrossings`. Snaps compare XZ alone, so a wall and the wall stacked on it are a dead tie and the wildcard picked between them on float noise — pointing at a ground wall's side within 0.75m of an upper wall's end node (a 1.5m-wide dead zone around every upper end, and node snaps outrank flanks) jumped the hover a storey, where the ride then drew a red ghost along the wall already standing there. Consequences: a node with no member on the filtered storey is skipped outright (`TryNodeSnap`), and a gesture keeps its ANCHOR's storey for the whole drag — the old `shapeBaseY ?? deckY` / `roomChainBaseY ?? deckY` fallbacks are gone, since with terrain-null they'd let a ground rect's side snap onto a deck it happened to run past.
- **The cursor ray names the storey, and a SIDE hit names it too** (`hoverSnapBase`, 2026-08-02): both resolvers set it — the slab/top-face base when there is one, otherwise the base of whatever wall the ray struck, and null (terrain) for terrain. It is NOT `hoverBaseY`: aiming at a ground wall's side means the ground storey while the gesture still stands on the terrain. This is the only thing that can tell a stack's co-located walls apart, so every hover-phase snap takes it instead of `deckY`. A snap onto an elevated wall still carries its storey in through `AdoptSnapElevation`, and from there `AdoptRideHostUnder` still locks the run to the wall below.
- **The planar graph is per-base** (2026-08-02; it used to be height-blind): `WallGraph.SameBase` (0.25m tolerance, −inf = terrain, and −inf never matches a finite base) filters `FindCrossings`, `OverlapsExisting`, `CoincidentCoverage`, `ResolveEndNode`, the distance/alignment guides, and **node identity** — `WallNode` carries its own `baseY` and `FindAt` takes one, because nodes are stored at y=0 and an upper wall's ends land directly above the lower wall's node. Without that they weld and one post tries to render two storeys of joint. **Any new query that compares XZ must take a base.**
- **No structural rules yet, deliberately** (user's call, 2026-08-02): nothing stores what rests on what, so deleting a wall leaves masonry above it hanging in the air. Build without rules first, add them later. `baseY` alone is enough to reconstruct support when that lands — don't add a spatial "what's under me" query in the meantime. Consequence to know: a room's roof reads its own ring edges' tops, so drawing a wall on top of a room's low wall does **not** make that room roofable (courses used to, via `NotifyCourseLaid`); `WallRoom.RetryRoofless` now fires on every `CommitEdge` instead.

## Placement state that expires

- **`EffectiveWallHeight` is only meaningful on the hover/click frame** (it reads the live hover snap). Anything a gesture needs later — height, locked-top plane, storey — must be **captured at the anchor click** (`shapeTopY`, `roomChainTopY`, `anchorSnapHeight`). Recomputing mid-drag silently substitutes the HUD height; that bug shipped once and cost a half-step misalignment.
- Ghost/overlay shells must scale about the **mesh bounds center** (`FitShell`), not the transform pivot — room slabs are world-space meshes on origin-pivoted objects, so pivot scaling translates them metres away.
- `WallGraph.DeleteSections` surgers an edge **once** (survivors are new edges with new indices) — pass all of an edge's doomed indices in a single call via the set overload.

## Edge geometry

- Section meshes are watertight only because neighbors evaluate the same curve at the same boundary parameter from one shared arc table. Section `tStart/tEnd` always lie in [0,1] now — the extended-arc machinery died with end extensions; edges cap flat exactly ON their node points.
- Section meshes are runtime-owned (`ownedMesh`, destroyed with the section). Preview meshes are preview-owned and always destroyed on rebuild/cancel — commit rebuilds fresh through the graph (no ownership transfer anymore).
- Colliders exist for cursor raycasts only (targeting, building on a wall top, delete) — never for occupancy.

## Input arbitration

- The scroll wheel has four meanings: camera dolly (default), wall height (Ctrl), curve bulge (bend phase), offset distance (Offset tool with a source selected). The last two claim the wheel via `GridPlacementSystem.ClaimingScrollWheel`; `FreeFlyCamera` checks it and Ctrl before dollying — any new wheel use must join this arbitration.
- **The HUD's modifier panel (top right) is generated from `GridPlacementSystem.ModifierHints`**, which reports the keys the tool in hand reads *in its current phase* (19 contexts: wall hover/drag, curved drag/bend, circle anchor/radius, rect anchor/side/width, room build/chaining/designate, delete, offset pick/placing, stair, door). Adding or moving a modifier means editing that method in the same commit — a panel that lists a key which does nothing is worse than no panel. Keys deliberately NOT listed where they do nothing: Shift in the curved drag, R outside the straight-build hover and the stair, Ctrl+scroll in Designate / Stair / Door (nothing is dialable in those three — the wall answers everything). The cutaway's `PgUp`/`PgDn`/`Home` are deliberately absent too: that panel reports what the *tool* reads, and the cutaway is a view control like the camera, so it carries its own keys in its own readout.
- No trigger colliders exist in the build scene, but raycast/overlap code still filters `isTrigger` — keep those filters when adding new triggers, or placement targeting will misread them.

## Tooling gotchas

- `manage_texture`'s `set_import_settings` MCP action silently drops its payload — set import settings via `execute_code` (editor API) or hand-edit the `.meta`.
- Screenshots taken the frame after a camera teleport used to smear — capture twice, keep the second. That was **TAA ghosting, not motion blur** (there is no MotionBlur override in the volume profile), and the camera moved to FXAA on 2026-08-05, so it is probably obsolete. Confirm on the next capture and delete this line.
- **`execute_code` that builds objects and then physics-tests them in the SAME call gets unsynced colliders** — the body walks through everything. Split across calls, or `Physics.SyncTransforms()` first.
- After script edits: `refresh_unity` (compile) + `read_console` for errors before proceeding; play-mode `execute_code` tests that delete-then-rebuild must use `DestroyImmediate` (deferred `Destroy` races validation).
- **The wall graph is play-mode only.** `WallEdge`/`WallNode`/`WallRoom` register in `OnEnable`, which Unity doesn't call in edit mode (no `[ExecuteAlways]`), so an edit-mode `execute_code` test builds unregistered objects: `FindAt` never shares nodes, no ring ever traces, and teardown that iterates `WallEdge.All` deletes **nothing** — the orphans stay in the scene and break the next run. Test in play mode; if you must clean edit-mode litter, scan with `FindObjectsByType`.
